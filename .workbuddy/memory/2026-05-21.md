## Bug Fix: training_tasks.py NoneType error

**Problem**: In `LLMT-backend/app/tasks/training_tasks.py`, the in-process training path (`trainer.train()`) would crash with `NoneType` errors because `create_trainer()` was called without `model`, `train_dataloader`, `eval_dataloader`, or `loss_fn`. Both `PyTorchTrainer` and `DeepSpeedTrainer` dereference `self.model` at the start of `train()` (e.g., `self.model.to(device)`), and `PyTorchTrainer` also calls `len(self.train_dataloader)`.

**Fix**: Before calling `create_trainer()`, added code to:
1. Build model via `ModelRegistry.get(model_type).get_model(config)`
2. Build dataset via `create_dataset_from_config(config_dict)`
3. Build dataloaders via `build_dataloaders(dataset, config_dict, distributed=...)`
4. Build loss_fn via `model_provider.get_loss_fn(config)`
5. Pass all four (`model`, `train_dataloader`, `eval_dataloader`, `loss_fn`) to `create_trainer()`

## Bug Fix: Celery revoke uses wrong task ID

**Problem**: `cancel_task()` in `training_service.py` called `celery_app.control.revoke(task.task_code, terminate=True)` using the business `task_code` (e.g., `TASK-A1B2C3D4`), but Celery's broker stores tasks by the UUID returned by `delay()` / `apply_async()`. The revoke was always a no-op — PostgreSQL status changed to "cancelled" but the worker process kept running.

**Fix** (3-layer approach):
1. **Model**: Added `celery_task_id` column to `TrainingTask` (stores `AsyncResult.id`)
2. **Service**: `create_task()` now saves `async_result.id` to `task.celery_task_id`; `cancel_task()` uses `task.celery_task_id` for revoke
3. **Worker**: Added `_CancellationCheckCallback` that polls DB every 10 steps via `on_step_end` — if status is "cancelled", sets `state.status = "cancelled"` so the trainer's `_should_stop()` exits the loop cooperatively

Also added `celery_task_id: Optional[str] = None` to `TrainingTaskOut` schema.

## Bug Fix: _get_trainer_script resolves nonexistent path

**Problem**: `_get_trainer_script()` in `training_tasks.py` computed the scripts directory by going 3 levels up from `__file__` (`LLMT-backend/app/tasks/` → `LLMT-backend/`), then appending `LLMT-training/examples`. But `LLMT-training/` is a **sibling** of `LLMT-backend/`, not a child — the resulting path `LLMT-backend/LLMT-training/examples/` doesn't exist. Distributed/megatron launches would fail with "script not found".

Also: `settings.LLMT_TRAINING_MODULE_PATH` was read but never used (dead code).

**Fix**: Rewrote `_get_trainer_script` with 3-level resolution:
1. `LLMT_TRAINING_SCRIPTS_DIR` (new settings field, env-var override) — absolute path
2. `LLMT_TRAINING_MODULE_PATH` if it points to an existing directory
3. Derived from repo layout: 4 `dirname` hops from `__file__` → `<repo>/`, then `LLMT-training/examples/`

Also added `LLMT_TRAINING_SCRIPTS_DIR: str | None = None` to `Settings` in `config.py`. Extracted `_script_name(framework)` helper.
